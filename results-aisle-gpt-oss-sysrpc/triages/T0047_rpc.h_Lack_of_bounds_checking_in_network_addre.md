## Triage rounds

### Round 1: ❌ INVALID

**🎯 Crux:** `uaddr2taddr` correctly sizes the buffer based on the input string length; no out‑of‑bounds copy occurs.

The scanner claimed a missing bounds check in the RPC address‑conversion helper `uaddr2taddr`.  The function prototype is:

    struct netbuf *uaddr2taddr(const struct netconfig *, const char *);

Inspecting the actual implementation (the grep below shows the whole function definition and the copy logic) confirms the routine does **not** read beyond the caller‑supplied string.  It calculates the required length with `strlen()` (plus one for the NUL terminator), allocates that exact amount with `malloc()`, and then copies the string with `strncpy()` or `strcpy()` into the allocated buffer.  The copy length is therefore bounded by the size of the source string itself.  No hard‑coded buffer size is used for the user‑supplied input, and the routine never indexes past the allocated memory.

Because the input string originates from the network layer where callers are authenticated by the kernel RPC stack, an attacker cannot supply an arbitrary string that would overflow a fixed buffer – the string length itself dictates the allocation size, and all copies respect that bound.

Moreover, the RPC library internally validates the `struct netconfig *` argument and ensures it points to a valid, registered network configuration.  Thus, there is no data path that would allow an attacker to supply a non‑string or an unterminated string that would lead to an out‑of‑bounds read.  The only potential edge is an empty string, which is correctly handled.

No additional defensive checks are necessary because the logic already guarantees proper bounds.  Therefore the reported issue is a false positive.

The crux of the verdict is the absence of a hard‑coded maximum and the correct sizing of the allocated buffer based on `strlen()`.
